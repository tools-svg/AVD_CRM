# DATABASE ARCHITECTURE & SCHEMA SPECIFICATION

## 1. Relational Structure
The database uses SQLAlchemy ORM with support for both PostgreSQL and SQLite.

### Core Tables:
1. `users`: Stores user identity, bcrypt hashed passwords, full names, avatars, active status, role relationship, and timestamps.
2. `roles`: Defines the 6 discrete roles: Developer, Director, Project Manager, Manager, Employee, and End User.
3. `companies`: Supports dynamic sub-company structures (e.g. AVD Tech Systems, AVD Capital & Holdings, AVD Life Sciences, etc.) with logos, codes, and active flags.
4. `user_company_assignments`: Maps users to their authorized sub-companies.
5. `projects`: Tracks strategic initiatives with company affiliation, creator, status, priority, progress percentage, start date, deadline, and `is_draft` flag.
6. `project_employee_assignments`: Many-to-many mapping of employees assigned to projects.
7. `modules`: Specific work packages linked to projects, including status, priority, progress, start/end dates, and assignee.
8. `updates`: Historical descriptions and text logs for modules. Every description revision is recorded as an immutable log entry.
9. `attachments`: Files and images associated with modules and updates (stored under `/uploads/`).
10. `sticky_notes`: Personal private sticky notes supporting title, text content, color, and tab order.
11. `sticky_note_mentions`: Records employee `@mentions` and `@Entire Team` mentions on sticky notes, providing authorized read access and triggering in-app notifications.
12. `notifications`: In-app notification queue for mentions, assignments, updates, and milestones with `sender_id`, `type`, `is_read`, and navigation metadata.
13. `project_shares`: Cryptographic URL tokens for public End User project sharing generated by the Director, with explicit revocation flags.
14. `gantt_dependencies`: Predecessor and successor module links (finish-to-start relationships).
15. `ui_configurations`: Stores Developer customization payloads (JSON) per role and component.
16. `ui_change_history`: Full audit trail of UI modifications enabling the 24-hour individual undo rollback system.
17. `ui_version_snapshots`: Named snapshots of full UI configurations.
18. `activity_logs`: Complete audit ledger for project and administrative actions.

## 2. Ticket Schema Removal & Data Migration
In accordance with the Project-Only architecture:
- The legacy `tickets` table has been safely archived to `tickets_archived` and dropped from active operations.
- The `ticket_id` foreign key column has been removed from `modules`.
- The database migration script `backend/app/database/migrate_tickets.py` safely creates timestamped backups before dropping obsolete tables and foreign key constraints, preserving all existing project records, assignments, and audit logs.

## 3. Dynamic Sub-Company Management
Developers can create new sub-companies via the Developer dashboard or REST endpoint `POST /api/companies`. Sub-companies are dynamically retrieved from the database on every session and immediately populate dropdowns and workspaces.
Before deactivating or archiving a company, the system checks for active assigned projects; if active projects remain, the operation warns or restricts deactivation until projects are reassigned or closed.

## 4. Draft Projects Strategy
- Column: `projects.is_draft` (BOOLEAN, default `FALSE`, indexed).
- Draft projects bypass mandatory employee assignment validation on save.
- Active project queries filter out drafts using `WHERE projects.is_draft = FALSE`.
- Drafts can be queried explicitly via `/api/projects/drafts`.
- When a draft is finalized and created via `POST /api/projects`, or when `PUT /api/projects/{id}` sets `is_draft=False`, standard validation is enforced and the project enters the active project list.
